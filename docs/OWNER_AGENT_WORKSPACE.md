# Technical Manager：对话式老板工作台

## 使用入口

本地演示：<http://127.0.0.1:8091/>。用现有 Owner 账号登录，进入 Assistant，沿用当前对话或点击 New conversation。

老板可以在一个持续对话里完成：描述目标 → 智能体查询真实记录 → 解释现状 → 展示待确认方案 → 修改要求 → 确认执行 → 查看结果及相关记录。

输入框上方的工具条可以直接打开 Reviews、Settings、Agents、Usage、Recovery、Evidence、Members、Releases、Updates、Activity。它们打开当前对话中的工作面板；不用切换页面也可以使用原有完整业务表单。Open page 保留为可选入口。

## 最适合第一次体验的连贯流程

### 1. 让智能体检查并准备候选

在 Owner 的 Assistant 输入：

> 请读取当前的 Coach 智能体版本和支持的模型。为我准备一个未发布的 Coach 候选，标签 Owner conversation demo，沿用当前可用 OpenAI 模型，额外要求：每次训练动作说明用清楚简短的英语，先给步骤，再解释原因。保留现有安全规则。先只给方案，等我确认再保存，不能发布或改变会员配置。

智能体会查询版本与支持模型，展示 Technical Manager 任务卡。卡片包含目标、变化说明、待执行步骤、具体参数和证据入口。此时应显示 Your decision，而不是已完成。点击 Review exact parameters 可以核对保存内容。

### 2. 连续修改方案

不要先点击 Confirm and run，直接在同一个输入框输入：

> 修改刚才这个候选方案：标签改为 Owner conversation demo revised，再加一条：每个动作说明最多三句话。之前的其他要求全部保留，仍然只保存未发布候选，不发布。

核对新卡片保留了原模型、安全要求、英语、先步骤后原因，并增加“三句话”约束。原方案应变为 Replaced by a newer proposal，不能再执行。

### 3. 确认并保存

点击新卡片的 **Confirm and run**，或输入：

> Confirm and run

系统执行已经展示的精确方案，不再让模型重新编写保存参数。完成后卡片显示 Actions recorded，出现保存回执。重复网络请求不会重复执行同一个任务。

这是保存候选，不是发布；会员使用的配置不会因此切换。需要正式使用时，仍要完成比较、人工评分、发布审核及执行等已有流程。

### 4. 在对话内查看结果

点击保存回执的 Open current record。Agent workshop 在当前对话上方打开，查看已保存候选的标签、模型、完整指令以及比较功能。

点击 **Continue conversation** 回到原对话。对话历史与输入草稿保留。若修改了未保存字段再关闭面板，会出现 Keep editing / Discard edits。

### 5. 同一入口处理其他工作

以下输入可以继续使用；具体数量、成员姓名和状态来自现场数据，不应预先编造：

> 检查现在需要我处理的事项，区分等待老板审核、已经批准但还没执行、以及需要技术排查的任务。告诉我先处理哪一项，并给我打开具体记录的入口。先不要修改任何东西。

> 查看当前的预算和模型调用额度，解释它们有什么区别。先只检查，不调整额度。

> 打开待审核申请的详情，我要在这个对话里查看证据并决定。

点击回答中的具体记录，或工具条 Reviews，在面板里检查申请内容并完成原有审核。敏感申请的完整材料由老板在本地业务面板查看；智能体只获得允许读取的运营元数据，不能声称自己审阅了不可见的健康资料。

## 哪些事情可以执行

| 工作 | 语言指令形成待确认方案 | 当前对话面板完整操作 |
|---|---|---|
| 服务配置提议、审核、执行 | 支持，各阶段分别保存状态 | Settings |
| 申请批准／拒绝 | 支持，遵守现有业务校验 | Reviews |
| 预算、调用额度、会员分组 | 支持，检查当前基线 | Usage / Members |
| 智能体候选保存、准备比较 | 支持 | Agents |
| 比较启动、逐项人工质量评分 | 在面板操作；不让模型虚构人工评分 | Agents |
| 发布提议、审核、执行、回滚与恢复提议 | 支持现有生命周期 | Releases |
| 故障前置条件、恢复、验证、关闭 | 支持现有业务校验 | Recovery |
| 证据、导出、用量核对、取消等完整操作 | 通过对应面板 | Evidence / Usage / Activity |

“一个对话框完成”包括当前对话内的交互面板，并不意味着每个人工评分或复杂表单都由模型自动填写。智能体只能调用明确注册的工具，没有任意 SQL、Shell 或 HTTP 执行权限。

## 关键实现文件

- `backend/app/owner_agent.py`：多轮理解、工具调用、持久化方案、旧方案替换、确认执行与回执。
- `backend/app/owner_tools.py`：只读证据工具和业务动作注册；调用已有服务，保留审核、版本与权限规则。
- `backend/app/database.py`：同一任务的业务写入和回执原子提交；后续步骤失败时整体回滚。
- `backend/app/chat.py`、`worker.py`、`model_gateway.py`：Owner 对话进入真实模型智能体运行流程。
- `frontend/src/OwnerTaskCard.tsx`：目标、变更、参数、证据、确认、执行结果卡片。
- `frontend/src/OwnerWorkPanel.tsx`：当前对话里的完整工作面板、内部导航、未保存编辑保护。
- `frontend/src/main.tsx`、`ConversationView.tsx`、`ownerNavigation.ts`：持续会话、自然语言确认、工具条与可选页面导航。
- `frontend/src/style.css`：卡片、面板与移动端样式。
- `backend/tests/test_owner_agent_integration.py`、`frontend/e2e/owner-agent.spec.ts`：数据库边界与浏览器交互检查。

## 验证口径

真实模型验证与自动化测试分开记录。浏览器固定数据测试验证的是布局、交互和请求路径，不证明模型理解能力。真实模型的输入、输出、任务状态和执行回执记录在本地 `.local/owner-agent-live.json`；测试日志位于 `.local/owner-agent-*.log`。这些本地文件不作为源码交付内容。

模型调用会使用当前额度和预算；额度不足时遵循现有等待和恢复机制。一次用户指令最多进行四轮模型推理，每轮最多三个读取工具。任务显示完成代表当前步骤已完成；保存候选不等于发布、提出恢复不等于已经恢复、后台工作排队不等于已经验证结果。
